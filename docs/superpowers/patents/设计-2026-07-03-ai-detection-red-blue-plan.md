# 专利文本 AI 生成嫌疑红队/蓝队方案

生成日期：2026-07-03

## 0. 边界

本方案不以规避 GPTZero 或其它检测脚本为目标，不使用“降 AI 率”“humanizer”“扰乱检测特征”等方式处理提交文本。

本方案的目标是把交底书从“AI 草稿式概括”重建为“发明人事实口径 + 代理人说明书口径 + 可核验工程证据”的正式材料。检测分仅作为风险信号，不作为优化目标。

## 2. 参考稿差异

### 2.1 原始技术交底书特征

文件：`智能座舱多模态交互融合方法及系统技术交底书.docx`

统计：

- 正文约 156 个非空段落。
- 平均行长约 56.6 字。
- 术语倾向：`权重` 42 次，`模块` 32 次，`动态` 19 次，`优化` 17 次，`提升` 17 次，`深度` 12 次，`精准` 10 次。

写法特征：

1. 保留研发材料形态，使用 `A1/A2/B1/B2/B3`、bullet、步骤 S1-S6。
2. 有大量具体实现参数，例如采样率、传感器位置、车速阈值、MFCC 维度、模型结构、训练数据规模、推理耗时。
3. 技术效果经常以“显著增强、同步提升、大幅优化、通用性强”等宣传性表达出现。
4. 每个步骤后写“本步骤技术效果”，但有些效果偏概括。
5. 替代方案写得较自然，包含取舍，例如成本增加、复杂度增加、依赖导航模块等。

### 2.2 代理一稿特征

文件：`QY-253571CN1-PA26009724-一稿-智能座舱多模态交互融合方法及系统.docx`

统计：

- 正文约 184 个非空段落。
- 平均行长约 103.8 字。
- 术语倾向：`所述` 96 次，`响应程度` 157 次，`一种可能的实现方式` 32 次，`本申请实施例` 31 次，`需要说明的是` 6 次，`示例性的` 5 次。

写法特征：

1. 代理人将“权重”大量上位为“响应程度/初步响应程度/目标响应程度”。
2. 说明书和权利要求共用同一条主线：获取数据 -> 确定初步响应程度 -> 基于历史交互和信息贡献量动态调整 -> 生成控制指令。
3. 删除或弱化原始交底书中的宣传式小标题。
4. 采用专利说明书稳定句式：
   - `一种可能的实现方式，...`
   - `具体的，...`
   - `示例性的，...`
   - `需要说明的是，...`
   - `本申请实施例对此不作具体限定`
5. 将具体数值移到实施例或示例中，并声明“不作具体限定”。
6. 技术效果绑定技术特征，不单独喊效果。
7. 背景技术更克制，避免把发明点写成现有技术启示。

### 2.3 质检表给出的硬规则

文件：`QY-253571CN1-PA26009724-专利质检表-智能座舱多模态交互融合方法及系统.doc`

实际扣分点：

1. 权利要求 1 直接记载具体权重信息，建议上位为响应程度或初步响应程度。
2. 权利要求 1 直接记载具体目标权重，建议上位为响应程度或初步响应程度。
3. 说明书形式问题。

可迁移规则：

1. 独权避免写死具体阈值、公式、数值和文件名。
2. 独权保留必要步骤与对象关系，具体参数放实施例。
3. 术语要统一，不能在同一概念上混用多个名字。
4. 技术效果要和技术特征、技术问题绑定。
5. 背景技术不能提前给出发明方案或技术启示。

2. 将未实现项改为可选实施方式或从属特征。
3. 强化真实代码依据：字段角色别名、A-D completeness 分级、failure signal 配置、cluster status、asset package/provenance。
4. 每个抽象对象至少配一个输入字段例子或输出字段例子。
5. 增加失败路径：置信度低、期望行为无法补全、聚类纯度不足、敏感信息命中、重复样本命中时如何降级。

3. “语义自由度账本 + 预算投影 + 轨迹反馈”的主线很强，但当前文本过于“理论完整”，缺少发明人实际实施中的小例子穿插。

4. 主权利要求不要写具体公式，只写“根据覆盖缺口、容量、风险状态和历史质量指标中的至少一项确定预算”。
5. 强化从属保护：语义自由度字段、约束图、裂变轨迹、反馈归因、带阻尼状态更新。

## 4. 红队工作流

### 4.1 检测器层

动作：

1. 将每份交底书按章节切分。
2. 每节独立跑检测或内部风险评分。
3. 标记高风险段落，但不按检测器直接改写。

输出：

1. 高风险段落清单。
2. 风险原因：套话、结构过齐、空泛、事实弱、公式堆叠、实现不一致。

### 4.2 文风层

检查项：

1. 是否连续使用同构句式，例如每段都“本申请通过...提高...”。
2. 是否有宣传词密集，例如显著、精准、深度、系统性、自动、智能、闭环。
3. 是否每节都是整齐列表，缺少说明书自然展开。
4. 是否只有概念名，没有输入、处理、输出、异常路径。
5. 是否过度使用英文变量名和 JSON 字段名。

### 4.3 事实层

检查项：

1. 该段是否能对应代码、文档、实施例或发明人口述。
2. 是否把“设计中”写成“已实现”。
3. 是否把“可选实施方式”写成“必要步骤”。
4. 是否出现产品名、内部路径、具体开源工具名等不宜写入正式交底书的内容。

### 4.4 代理人质检层

检查项：

1. 独权是否包含不必要具体参数。
2. 权利要求是否缺少必要技术特征。
3. 背景技术是否包含发明点启示。
4. 技术效果是否脱离技术特征。
5. 实施例是否只是重复发明内容。
6. 术语、模块名、数据对象名是否统一。

## 5. 蓝队改写工作流

### 5.1 不逐句洗稿

禁止路径：

1. 逐段投入 BypassAIGC。
2. 只替换同义词。
3. 为降低检测分故意加入口语、错别字、非正式表达。
4. 打散专利必要结构。

采用路径：

1. 按事实卡片重写。
2. 按代理人说明书句式重组。
3. 用实施例、异常路径和限制条件替代空泛效果。
4. 保留修订说明和事实来源。

### 5.2 段落改写模板

每个核心段落用以下结构重写：

```text
本实施例中，系统先接收/读取/获取 [具体输入]。
系统根据 [字段、规则、状态或约束] 执行 [处理动作]。
当 [条件] 满足时，生成/写入/更新 [具体输出对象或字段]。
若 [异常或低置信条件]，则 [降级、复核、候选队列或不进入正式资产]。
通过上述处理，能够针对 [具体技术问题] 减少/避免 [具体风险]。
```

### 5.3 术语上位规则

| 草稿高风险写法 | 蓝队上位写法 |
| --- | --- |
| 固定权重、固定比例 | 响应程度、分配结果、预算结果、调节参数 |
| 自动生成所有资产 | 根据预设规则生成候选资产，或进入复核队列 |
| AI 诊断/智能诊断 | 根据字段、备注、工具记录和上下文确定失败信号 |
| 完整闭环 | 记录反馈并用于后续处理参数调整 |
| qualityScore 必然计算 | 一个实施例中可计算质量指标 |
| clusterPurity 必然计算 | 可根据问题族内一致性确定质量状态 |
| tool_argument_error 已实现 | 一个可选失败信号或从属实施方式 |

### 5.4 技术效果绑定规则

不要写：

```text
本申请显著提高数据资产生产效率，并降低训练评测污染风险。
```

改为：

```text
由于系统在生成资产前记录资产用途，并在完整度不足或期望行为置信度不足时将证据转入复核队列，因此同一失败证据不会在未确认用途的情况下同时进入训练候选和回归评测文件，从而降低训练数据与评测数据混用的风险。
```

### 5.5 实施例增强规则

每个实施例至少包含：

1. 输入样例。
2. 字段识别或自由度识别过程。
3. 中间对象。
4. 输出文件或输出样本。
5. 异常/降级路径。
6. 为什么该路径解决对应技术问题。

## 7. 当前判断

主要矛盾不是“检测分高”，而是“文本呈现方式过像完整 AI 生成稿，缺少发明人材料与代理人加工后的事实纹理”。

解决方向不是洗文本，而是重建证据链和说明书口径：

1. 事实来自代码、测试、docs、实施例。
2. 抽象概念必须落到输入、处理、输出、降级路径。
3. 权利要求用上位概括，实施例承载具体参数。
4. 技术效果必须绑定技术特征。
5. 检测器只用于发现可疑段落，不用于指导规避。
