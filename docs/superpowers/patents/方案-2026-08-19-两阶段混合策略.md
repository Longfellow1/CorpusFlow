# 专利返工两阶段混合策略

生成日期：2026-08-19  
背景：企业审核大概率用检测工具直接查，查到疑似就打回

---

## 核心判断

1. **审核现状**：不细看内容，用检测工具（类似GPTZero）查文本概率和逻辑
2. **检测原理**：
   - Perplexity（困惑度）：人类写作变化大，AI写作概率分布平滑
   - Burstiness（突发性）：人类句子长短变化大，AI更均匀
   - 段落模式：AI倾向整齐列表、排比句、"为了...便于...从而..."
3. **纯蓝队方案风险**：虽然技术事实正确，但文本模式仍像AI生成 → 被检测工具打回

---

## 两阶段混合策略

### 🛡️ 阶段一：建立事实防线（2小时，AI独立完成）

**目的**：万一被质询"这是AI写的吗"，有证据自证清白

**产出物**：
1. **事实锁定表v2**（技术特征 vs 代码证据 vs 代码行号）
2. **术语一致性表**（交底书术语 vs 代码术语 vs 证据位置）
3. **实施例来源表**（每个实施例 vs fixture数据位置/代码逻辑位置）
4. **AI使用说明**（声明AI只用于检索/形式审查，技术方案来自代码和产品文档）

**关键**：这4份文档不提交给审核，只作为应对质询的**备份证据**

---

### 🔄 阶段二：BypassAIGC降检测分（1小时，AI辅助）

**输入**：
- 现有交底书（主案/第二案）
- 企业规范硬性指标（技术问题≤2个、实施例≥3个≥5页、附图≥3幅）
- 阶段一产出的事实锁定表

**处理流程**：

```
┌─────────────────┐
│ 1. 预处理修正   │ ← 先改企业规范硬性违规项
└────────┬────────┘
         ↓
┌─────────────────┐
│ 2. BypassAIGC改写│ ← 降检测分
└────────┬────────┘
         ↓
┌─────────────────┐
│ 3. 事实对齐验证  │ ← 用事实锁定表验证技术事实是否被改坏
└────────┬────────┘
         ↓
┌─────────────────┐
│ 4. 人工定向修正  │ ← 你只改被改坏的技术事实（预计5-10处）
└─────────────────┘
```

**关键控制点**：
- 步骤3：AI自动对照事实锁定表，标注"这里被BypassAIGC改坏了"
- 步骤4：你只需要修正被标注的地方（预计10-15分钟）

---

## 风险控制

### 风险1：BypassAIGC改坏技术事实

**应对**：
- 用阶段一的事实锁定表自动验证
- AI标注"被改坏的地方" → 你定向修正（不是全文重写）
- 预计被改坏的地方：5-10处（术语、数值、逻辑关系）

### 风险2：被质询"这是AI写的吗"

**应对**：
- 拿出阶段一的4份证据文档
- 证明"技术方案来自代码（给行号）和产品文档，AI只用于语言润色"
- 关键：你能对着代码解释每个技术特征，不是背AI生成的文本

### 风险3：违反企业规范编码15

**应对**：
- AI使用说明中措辞："发明构思和技术方案来自发明人和项目代码，AI用于语言表达优化和形式规范检查"
- 关键：这是事实（阶段一证明了技术方案确实来自代码）
- BypassAIGC只改"怎么说"，不改"说什么"
