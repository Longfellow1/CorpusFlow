```
大语言模型应用在实际运行时会产生失败案例，这些失败案例通常散落在评测日志、用户反馈、人工标注表或运行trace中。现有做法通常是人工挑选部分失败案例加入评测集或负例库，但这种做法存在明显问题。

失败证据的字段来源多样、命名不一致，难以统一处理。同样是"用户输入"，可能记作 `query`、`user_message`、`instruction` 或 `prompt`；同样是"实际输出"，可能记作 `output`、`response`、`actual` 或 `result`。如果只按固定字段名读取，会导致大量失败证据无法识别。

另一个普遍情况是失败证据中缺失关键信息，但缺失类型不同、可补全程度不同。部分证据缺期望行为，部分缺上下文，部分缺执行信息。现有方法通常直接丢弃不完整证据，或人工补全后再处理，导致数据利用率低、人工成本高。

此外，失败原因难以归类和追溯，同类问题重复出现。失败证据通常只记录"测试未通过"，但无法说明是工具未调用、工具参数错误、上下文缺失还是输出格式问题。无法按失败原因聚类管理，导致相同问题反复出现、修复策略分散。

最后，不同失败原因适合生成不同类型的数据资产，但现有方法缺少分流机制。工具调用失败适合生成训练样本、输出格式错误适合生成负例、多轮对话失败适合生成回归评测用例，但现有方法通常只生成单一类型资产，无法按问题特征匹配资产用途。

基于上述问题，需要一种能够自动识别失败证据的字段角色、补全或标记缺失信息、按失败原因聚类、按问题特征生成对应类型数据资产并记录来源的方法。
```

## 第二案检测结果

### 需要手工改顺的段落（3处）

#### 1. B1技术问题 - 第一/第二/第三的连续排比

**当前文本**：
```
**第一,无法说明哪些语义维度允许变化、哪些必须保持不变。**
**第二,不同语义维度之间存在约束关系,但现有方法缺少约束管理机制。**
**第三,扩写过程缺少可追溯的生成轨迹和质量反馈闭环。**
```

**建议改为**（打散排比）：
```
为大语言模型构建训练或评测语料时，通常只能获得少量真实种子语料，但真实种子往往同时包含意图、参数、实体、条件、排除项、多轮承接关系等多个语义维度。需要从少量种子扩写到大批量语料，以覆盖不同参数值、实体组合、表达方式和场景变化。

现有的语料扩写方法主要包括同义改写、模板填槽、实体替换和生成后筛选等。这些方法存在以下问题。

首先，无法说明哪些语义维度允许变化、哪些必须保持不变。例如"把空调调到22度"中，"空调"是设备对象（可替换为"暖气"），"22度"是参数值（可替换为其他温度），但"调到"的目标方向（升温/降温）受参数值约束，不能任意变化。现有方法通常整句改写或单独替换某个词，无法区分语义不变量与可变语义维度，导致扩写后语义漂移。

其次，不同语义维度之间存在约束关系，但现有方法缺少约束管理机制。例如"找附近的店，但不要便利店"中，"附近"和"便利店"可独立变化，但"不要"是排除关系，如果同时改变"找"和"不要"，可能破坏排除边界。又如"不是的，在QQ音乐里播放"是多轮纠偏，前文对话决定了哪些词可以变化、哪些词是纠偏目标必须保持。现有方法通常孤立扩写单个维度，忽略维度间的互斥、联动和条件激活关系，导致扩写后语义自洽性破坏。

另外，扩写过程缺少可追溯的生成轨迹和质量反馈闭环。生成后筛选方法虽然可以过滤不合格样本，但无法说明不合格原因是哪个维度越界、哪两个维度组合破坏了约束，也无法将失败信息反馈到下一轮生成中调整策略。这导致大规模扩写时重复生成失败样本、浪费计算资源，且问题样本无法归因。

基于上述问题，需要一种能够从种子中识别语义不变量与可变语义维度、管理维度间约束关系、记录每条样本的生成轨迹并将质量反馈用于调整后续生成策略的语料扩写方法。
```

#### 2. S2识别不变量与可变维度 - 列表密集

**当前文本**：

```
可变语义维度:
- **来源片段**(在种子中的位置)
- **依赖的不变量**(如参数值变化不能破坏意图方向)
- **允许的扩写操作**(值域扩展/实体替换/表达改写/场景迁移)
- **禁止的扩写操作**(避免破坏不变量)

```

**建议改为**（打散列表为自然段落）：
```
对每个可变语义维度，系统需要提取其在种子中的来源片段、依赖的不变量（如参数值变化不能破坏意图方向）、允许的扩写操作（值域扩展、实体替换、表达改写、场景迁移）、禁止的扩写操作（避免破坏不变量）以及与其他维度的约束关系（互斥、联动、条件激活）。
```

#### 3. B3技术效果 - "由于SX...能够..."连续6条

**建议改为**（与主案类似，变化句式）：
```
本发明的技术效果包括：

语义骨架构建和不变量识别（S1-S2）能够明确区分哪些语义必须保持、哪些维度允许变化，避免整句改写或单独替换词汇导致的语义漂移。

维度约束图（S3）使得系统能够管理维度间的互斥、联动、条件激活和顺序依赖关系，避免多个维度同时变化时破坏排除边界、条件关系或多轮承接关系。

样本级扩写计划（S4）在生成前确定哪些维度开启、哪些维度锁定及其联合调度方式，而非生成后再筛选，减少无效生成。

生成轨迹记录（S5）使每条候选语料可追溯到具体维度、扩写操作和约束边激活情况，使问题样本可归因到具体维度和操作。

维度级反馈和调整机制（S6）能够将语义越界、约束破坏、重复等失败信息转化为维度级调整策略，改变下一轮扩写计划，而非仅丢弃单条失败样本。

相比模板填槽、实体替换或生成后筛选，本方法在从少量种子扩写到大批量语料时，能够同时控制语义不变量保持、维度约束满足、轨迹可追溯和反馈闭环调整。
```
