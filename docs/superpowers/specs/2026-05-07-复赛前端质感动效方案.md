# CorpusFlow 复赛前端质感动效方案

日期：2026-05-07

目标：在不改变主流程、不增加用户理解成本的前提下，为复赛版本补一层“专业、精密、可信”的前端动效质感。动效服务于主路径：**导入 → 识别 → 生成 → 结果 → 导出**。

核心判断：复赛阶段不做大面积视觉改版，不做复杂 3D，不做粒子背景。只做少量高质量微动效，让评委感觉产品是“完成度高的工程工具”，不是临时 Demo。

---

## 1. 设计原则

### 1.1 简约但有仪式感

动效只出现在关键状态变化处：

- 文件被读取
- 字段被识别
- 生成开始
- 结果落位
- 拒识命中
- 导出完成

普通 hover、表单输入、静态说明不额外加戏。

### 1.2 数据流动感

CorpusFlow 的核心卖点是“把原始数据变成训练资产”。视觉上要让用户感知到数据在流动、归档、被处理，而不是页面在跳。

关键词：

- 归位
- 扫描
- 落位
- 盖章
- 归档

### 1.3 专业工具感

复赛视觉不要像游戏、营销页或 AI 聊天玩具。应该更像：

- 数据工作台
- 工业仪表
- 代码审查工具
- 专业标注平台

动效节奏要短、稳、克制。多数动效控制在 120ms-420ms。

---

## 2. 推荐上线范围

复赛只做 P0 + P1。P2 作为时间充裕时的锦上添花。

| 优先级 | 动效 | 价值 | 风险 |
|---|---|---|---|
| P0 | 字段识别吸附动画 | 强化“自动理解数据”的可信感 | 低 |
| P0 | 生成进度扫描线升级 | 强化“系统正在工作”的感知 | 低 |
| P0 | 结果卡片逐条落位 | 让结果像被整理归档 | 低 |
| P0 | 导出完成反馈 | 强化闭环动作 | 低 |
| P1 | 拒识标签盖章感 | 强化安全边界与可审计 | 低 |
| P1 | 精调步骤进度轨道 | 强化专业流程感 | 中 |
| P2 | 首页任务卡细光边 | 首屏更有质感 | 低 |
| P2 | 数字缓动 | 让保留数、完成数更顺滑 | 中 |

---

## 3. P0 动效设计

### 3.1 字段识别吸附动画

使用位置：快速任务导入完成后，字段识别区。

当前用户看到：

```text
用户问题 Instruction
query

补充材料 Input
input

期望输出 Output
output

助手角色 System
system
```

目标体验：

上传完成后，字段 chip 不要突然出现，而是从轻微偏移状态滑入并稳定下来。

建议表现：

- 每个字段 chip 延迟 40ms 依次出现。
- 初始状态：透明度 0，Y 方向偏移 6px，边框亮度略高。
- 结束状态：透明度 1，Y 归零，边框恢复常态。
- 总时长：180ms-260ms。

产品意义：

- 让用户感到“系统确实识别了字段”，不是静态展示。
- 对 `query -> Instruction` 这类信任点尤其重要。

验收标准：

- 上传后字段区域有轻微、连续的出现动效。
- 不影响字段文字可读性。
- 导入大文件时不阻塞页面。
- 重复上传文件时动效可以再次触发。

不做：

- 不做字段飞线。
- 不做复杂路径动画。
- 不做过强发光。

---

### 3.2 生成进度扫描线升级

使用位置：快速任务生成进度卡、精调生成进度。

目标体验：

进度条不仅显示百分比，还能通过一条细扫描线表达“系统正在处理”。

建议表现：

- 进度条主体保持当前绿色或靛蓝。
- 在运行中，进度条内部有一条窄高光从左到右扫过。
- 扫描线宽度控制在进度条宽度的 12%-20%。
- 扫描线透明度 35%-70%，不要刺眼。
- 停止、完成、失败状态停止扫描。

产品意义：

- 解决“进度条看起来不动”的信任问题。
- 比 spinner 更像专业任务系统。

验收标准：

- 生成中有扫描线。
- 暂停或完成时扫描线停止。
- 进度百分比仍以真实任务完成数为准。
- 不能出现一开始满条的错觉。

不做：

- 不做全屏 loading。
- 不做多条扫描线。
- 不做闪烁警报感。

---

### 3.3 结果卡片逐条落位

使用位置：快速任务结果列表、精调生成结果列表。

目标体验：

生成完成后，结果不是突然全量刷出，而是按 seed 分组轻微落位。

建议表现：

- Seed 分组先出现。
- 组内结果卡片按 40ms-80ms 间隔依次出现。
- 初始状态：透明度 0，Y 方向偏移 8px。
- 结束状态：透明度 1，Y 归零。
- 如果结果超过 30 条，只对首屏或前 12 条做 stagger，避免性能浪费。

产品意义：

- 让“批量结果被系统整理好了”的感觉更强。
- 避免结果区突然变化造成用户视觉跳跃。

验收标准：

- 结果出现有层次。
- 大批量结果不明显卡顿。
- 滚动位置稳定，不因为动效导致页面乱跳。

不做：

- 不做弹跳。
- 不做卡片旋转。
- 不做过大的 scale 动画。

---

### 3.4 导出完成反馈

使用位置：JSON / CSV / JSONL 导出按钮。

目标体验：

用户点击导出后，按钮短暂反馈“已导出”，让闭环动作有明确完成感。

建议表现：

- 点击导出时按钮进入 loading 状态。
- 导出成功后按钮文案短暂变为：
  - `已导出 JSON`
  - `已导出 CSV`
  - `已导出 JSONL`
- 显示 900ms-1200ms 后恢复原文案。
- 可以在按钮右侧短暂出现一个小文件 chip，例如 `corpusflow.jsonl`。

产品意义：

- 导出是比赛演示闭环的最后一步，必须给用户“完成了”的明确反馈。
- 比单纯下载文件更有产品完成度。

验收标准：

- 导出成功有明确反馈。
- 导出失败显示错误，不显示成功态。
- 连续点击不会造成多个状态叠加。

不做：

- 不做 toast 堆叠。
- 不做大弹窗。
- 不做下载完成烟花。

## 4. P1 动效设计

### 4.1 拒识标签盖章感

使用位置：拒识 seed、结果区拒识行。

目标体验：

拒识不是“报错”，而是系统完成了一次安全判定。视觉上更像盖章，而不是警报。

建议表现：

- `拒绝 · 原因` 标签出现时轻微 scale：0.96 → 1。
- 透明度：0 → 1。
- 时长：160ms-220ms。
- 颜色保持当前玫红/红色系，但不要闪烁。

产品意义：

- 强化“工具有边界、有安全判断、有审计记录”。
- 对比赛评委输入敏感句时很有说服力。

验收标准：

- 拒识行能保留在列表里。
- 拒识标签出现有短促确认感。
- 不制造恐慌感。

---

### 4.2 精调步骤进度轨道

使用位置：精调生成工作台 1/2/3/4 阶段。

目标体验：

用户能感受到自己处在一个“生产流程”里，而不是很多卡片堆叠。

建议表现：

- 左侧或阶段数字之间增加一条细进度轨道。
- 当前阶段高亮，已完成阶段低亮。
- 阶段切换时高亮条滑动到下一阶段。
- 时长：220ms-320ms。

产品意义：

- 强化精调模式的专业感。
- 让“种子 → 解析 → 仿写 → 训练样本”更像流水线。

验收标准：

- 不压缩原有内容空间。
- 不新增解释性文字。
- 阶段状态和实际数据状态一致。

风险：

- 精调页面结构较重，改动前要确认不会影响当前布局。
- 这项放 P1，不挡复赛上线。

---

## 5. P2 锦上添花

### 5.1 首页任务卡细光边

首页“精调生成 / 快速任务”两个入口卡片，在 hover 时可以有一条极细的边缘光从左上角滑过。

目的：

- 增加首屏质感。
- 让入口卡片更像可操作工作台，而不是静态卡片。

约束：

- 只 hover 触发。
- 光边透明度低。
- 不做循环动画。

### 5.2 数字缓动

适用数字：

- 已完成 0/5
- 保留 10
- 保留率 100%
- 有效 2 / 4 行

目的：

- 数字变化更顺滑。
- 让进度感更强。

约束：

- 只对小范围关键数字做。
- 不为了数字动效引入复杂状态管理。
- 不影响真实进度准确性。

---

## 6. 不做清单

复赛版本明确不做：

- 粒子背景
- 3D 翻转卡片
- 大面积动态渐变
- 打字机效果
- 全屏 loading
- 页面切换夸张缩放
- 音效
- 鼠标尾迹
- 彩色烟花或庆祝动画
- 为动效重构主流程

原因：

- 容易显得廉价。
- 影响专业工具定位。
- 增加移动端和录屏风险。
- 复赛更需要稳定和可信，不需要“网页特效秀”。

---

## 7. 上线顺序

### 第一批：复赛必做

1. 字段识别吸附动画
2. 生成进度扫描线升级
3. 结果卡片逐条落位
4. 导出完成反馈

这四项覆盖完整主路径，ROI 最高。

### 第二批：复赛前有时间再做

5. 拒识标签盖章感
6. 精调步骤进度轨道

这两项提升质感，但不影响核心闭环。

### 第三批：决赛或正式展示再做

7. 首页任务卡细光边
8. 数字缓动

这两项偏 polish，不应挤占主路径稳定性。

---

## 8. 验收 Checklist

### 产品验收

- [ ] 用户能明确感知上传后字段被识别。
- [ ] 生成过程中页面不是静止的，但也不喧宾夺主。
- [ ] 结果出现有整理感，不突然整屏跳变。
- [ ] 拒识内容能被看到，并且像安全判定而不是系统错误。
- [ ] 导出后用户能明确知道导出成功。

### 视觉验收

- [ ] 动效整体克制，不超过专业工具气质。
- [ ] 不出现大面积闪烁、强光、过度渐变。
- [ ] 暗色主题下文字对比度不下降。
- [ ] 中文和英文字段标签仍清晰可读。
- [ ] 录屏 1080p 下动效可见但不抢画面。

### 工程验收

- [ ] `npm run lint` 通过。
- [ ] `npm run build` 通过。
- [ ] 快速任务主路径可跑通：上传、识别、生成、拒识、导出。
- [ ] 精调主路径可跑通：种子、预览、指令微调、生成。
- [ ] 动效不依赖真实网络速度，慢接口和快接口都有合理表现。
- [ ] `prefers-reduced-motion` 用户可以减少非必要动画。

---

## 9. 评委视角预期效果

评委看到的不是“页面很花”，而是：

- 上传后字段自动归位，说明工具能理解表格。
- 生成时进度稳，不像卡住。
- 结果按组落位，说明系统在整理数据资产。
- 敏感样本被拒识且保留原因，说明工具有安全边界。
- 导出反馈明确，说明从输入到产出闭环完整。

一句话总结：

> 复赛动效目标不是炫技，而是让 CorpusFlow 看起来像一套成熟的数据生产系统。
