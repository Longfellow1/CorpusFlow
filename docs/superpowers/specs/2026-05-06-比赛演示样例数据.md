# CorpusFlow 比赛演示样例数据

日期：2026-05-06

用途：为比赛 PPT、线上演示和录屏准备可挑选的代表性 case。覆盖两个演示模式：

- 快速任务台：批量导入、字段识别、快速生成、导出 JSON/CSV/JSONL。
- 精调生成工作台：单条高价值种子、语义骨架、候选扩写、训练样本预览。

选择原则：

- 同一组内主题统一，评委容易理解。
- 包含短句、普通句、长句、长难句。
- 覆盖多个业务类别：车载助手、旅游生活、电商客服、企业知识库、政务办事、教育学习、金融客服。
- 避免真实个人隐私、真实订单号、真实身份证号、真实密钥。
- 避免医疗诊断、投资建议、法律结论等高风险场景。
- expected 字段只描述期望行为，不写死不可验证事实。

## 推荐演示组合

### 正式演示组合 V1：车载 / 音乐 / 本地生活

这是当前推荐用于 Cloudflare 线上演示和正式录屏的一组。它不使用边界难例，优先选择稳定、直观、可泛化的指令。

快速任务 CSV：

```csv
query,expected
帮我把空调打开到22度,识别车载空调控制意图，生成温度、动作和设备表达的多样化训练样本
周杰伦最近有新歌吗,识别音乐查询意图，生成歌手、作品类型和时间表达的多样化训练样本
找一下附近好吃的川菜馆,识别本地餐饮搜索意图，生成位置、菜系、口味和推荐约束的多样化训练样本
导航去虹桥机场，尽量避开拥堵,识别导航规划意图，生成目的地、路线偏好和避堵表达的多样化训练样本
帮我查一下附近有没有能充电的停车场,识别车载补能和停车搜索意图，生成充电、停车、距离和可用性相关样本
```

演示参数：

```text
并发：4
每条种子目标数量：保持当前产品默认/现状
过滤强度：保持当前产品默认/现状
仿写相关参数：保持当前产品默认/现状，不调低
生成意图：生成用于训练车载与生活助手的高质量指令样本，保留用户原始意图，扩展实体、动作、数值、时间和位置表达，避免编造不可验证事实。
```

选择理由：

- 覆盖车控、音乐查询、本地生活、导航和补能停车。
- 三条精调 case 的泛化点显性，评委容易看懂。
- 比餐饮闲聊、政务金融、复杂旅游规划更稳。
- 避免开放闲聊导致生成泛化过宽。

### 正式精调 Case V1

这三条建议提前预制到演示任务的初始种子里，录屏时直接打开，不临场输入。

#### FT-DEMO-01：车控指令

```text
帮我把空调打开到22度
```

展示点：

- 设备泛化：空调 -> 座椅加热 / 座椅通风 / 方向盘加热
- 数值泛化：22度 -> 18 / 19 / 20 / 24 / 28 度
- 动作泛化：打开 -> 开 / 开一下 / 调到 / 设置成 / 帮我调
- 表达泛化：帮我把空调打开到22度 -> 空调调到22度 -> 车里太热了，把空调开到22度

#### FT-DEMO-02：音乐查询

```text
周杰伦最近有新歌吗
```

展示点：

- 歌手泛化：周杰伦 -> 林俊杰 / 陈奕迅 / Taylor Swift / 五月天
- 作品泛化：新歌 -> 新专辑 / 最新单曲 / 最近发布的歌 / 好听的新歌
- 时间泛化：最近 -> 近期 / 最新的 / 这段时间 / 今年
- 意图泛化：有没有新歌 -> 推荐新歌 / 查新专辑 / 播放最新作品

#### FT-DEMO-03：本地餐饮搜索

```text
找一下附近好吃的川菜馆
```

展示点：

- 位置泛化：附近 -> 公司附近 / 当前位置附近 / 三公里内 / 虹桥附近
- 菜系泛化：川菜馆 -> 北京菜 / 杭帮菜 / 湘菜 / 粤菜 / 日料
- 偏好泛化：好吃 -> 评分高 / 适合聚餐 / 不太辣 / 性价比高
- 动作泛化：找一下 -> 推荐 / 查一下 / 帮我看看 / 搜一下

### 稳妥组合 A：车载 + 生活助手

适合录屏主线，直观、低风险、容易讲清楚“意图保持”和“实体扩展”。

使用：

- 快速任务：选择 `Group A` 的 3-5 条。
- 精调生成：选择 `A-FT-01` 或 `A-FT-03`。

优点：

- 场景真实，评委容易代入。
- 包含路线、餐厅、天气、停车等实体扩展空间。
- 不涉及敏感行业。

### 稳妥组合 B：企业知识库助手

适合强调“数据资产闭环”和“内部知识问答微调”。

使用：

- 快速任务：选择 `Group D` 的 3-5 条。
- 精调生成：选择 `D-FT-02`。

优点：

- 和“微调数据工程平台”的定位更贴。
- 展示从 FAQ / 工单 / SOP 到训练样本的生产流程。
- 适合 PPT 技术实现页。

### 展示复杂度组合 C：混合长难句

适合展示 CorpusFlow 能处理复杂语义，但不建议全部用于正式录屏。

使用：

- 快速任务：从 `Long / Hard Cases` 中选 2 条，加 2 条短句。
- 精调生成：选择 `H-FT-01`。

优点：

- 能展示语义骨架和质量过滤价值。
- 但生成可能更慢，正式录屏需控制数量。

## 不建议用于正式录屏的 Case

下面这些类型可以放在 PPT 或说明里，但不建议作为正式录屏主路径：

- 金融理财收益解释：容易被评委追问合规边界。
- 政务政策办理：容易被追问地区政策准确性。
- 企业技术排障长难句：展示效果强，但生成更慢，口播解释成本高。
- 太长的综合旅游规划：容易把演示节奏拖慢。

## 录屏挑选建议

正式录屏只用 3-5 条种子：

- 1 条短句：展示系统能快速处理直接需求。
- 1-2 条普通句：展示常见业务场景。
- 1 条长句：展示多约束处理。
- 最多 1 条长难句：展示语义骨架价值。

不建议一次导入太多：

- 生成等待时间不可控。
- 评委看不清每条 case 的代表性。
- 录屏更容易跑偏成操作流水账。

推荐正式参数：

```text
并发：4
每条种子目标数量：保持当前产品默认/现状
过滤强度：保持当前产品默认/现状
仿写相关参数：保持当前产品默认/现状，不调低
生成意图：生成用于训练车载与生活助手的高质量指令样本，保留用户原始意图，扩展实体、动作、数值、时间和位置表达，避免编造不可验证事实。
```
