# CorpusFlow 比赛演示材料准备

日期：2026-05-06

目标：在算法服务修复并稳定后，快速完成 Cloudflare Pages 前端发布、比赛 PPT、4-5 分钟录屏和样例产出包。

当前原则：

- 不做 Cloudflare-only 改造。
- 不迁移 Express API 到 Pages Functions。
- 不迁移 FastAPI 算法服务到 Python Workers。
- 第一版优先拿到稳定演示 URL：Cloudflare Pages 前端 + 外部容器后端。
- API key、JWT secret、`.env.local`、终端密钥不进入 PPT、录屏和公开材料。

## 1. 当前分工

### 算法 agent 负责

- `algorithm/` 下 FastAPI 算法服务修复。
- LLM 调用稳定性、超时、错误处理、进度、暂停/取消。
- `/health`、`/quick-generate`、`/progress/:jobId` 等算法接口行为。
- 输出最终接口变更、环境变量变更、已验证命令和剩余风险。

### 本材料负责

- Cloudflare Pages 非代码发布准备。
- 演示环境变量清单。
- 线上验收 checklist。
- PPT 大纲和每页文案。
- 录屏路径、旁白、样例 CSV。
- 等算法 agent 修完后，辅助做只读集成复核。

## 2. 推荐部署形态

```text
用户浏览器
  -> Cloudflare Pages
  -> React/Vite 静态前端
  -> VITE_API_BASE_URL
  -> 外部 Express API
  -> 外部 FastAPI 算法服务
  -> Ark / 豆包模型
```

选择理由：

- 前端是标准 Vite React 应用，Cloudflare Pages 可直接构建。
- 当前 Express API 依赖本地 JSON 文件和常驻 Node 服务，不适合直接作为 Pages 静态站运行。
- 当前 FastAPI 算法服务包含 LLM 编排、长任务、进度状态和取消逻辑，不建议比赛前迁移到 beta 或边缘运行时。
- 比赛提交更看重稳定可访问 URL 和完整演示链路，而不是一次性完成 Cloudflare-only 架构。

Cloudflare 官方依据：

- Vite / React Pages 构建配置：`npm run build`，输出目录 `dist`。
- Direct Upload 可用 Wrangler 或拖拽上传预构建资产。
- 如果包含 `functions/` Pages Functions，需用 Wrangler 上传，dashboard 拖拽不支持完整 Functions 编译链路。

参考链接：

- <https://developers.cloudflare.com/pages/configuration/build-configuration/>
- <https://developers.cloudflare.com/pages/get-started/direct-upload/>
- <https://developers.cloudflare.com/workers/wrangler/commands/pages/>

### Git 集成发布

推荐用于正式演示项目。

```text
Framework preset: Vite / React
Build command: npm run build
Build output directory: dist
Node version: 22
Production branch: main 或最终比赛提交分支
```

环境变量：

```text
VITE_API_BASE_URL=https://api.example.com
NODE_VERSION=22
```

注意事项：

- `VITE_` 前缀变量会进入前端构建产物，只能放公开 API base URL。
- 不要在 Cloudflare Pages 前端环境变量里放 `ARK_API_KEY`、`JWT_SECRET`。
- 如果 API 与 Pages 不同域，Express API 必须允许 Pages 域名跨域访问。
- Cloudflare Pages 默认构建镜像已使用 Node 22，但显式设置 `NODE_VERSION=22` 可减少环境漂移。

### Dashboard 手工操作

Cloudflare Pages 正式发布步骤：

1. 打开 Cloudflare Dashboard。
2. 进入 `Workers & Pages`。
3. 点击 `Create application`。
4. 选择 `Pages`。
5. 选择 `Import from an existing Git repository`。
6. 连接 GitHub，并授权 CorpusFlow 仓库。
7. 选择最终封版分支。
8. 设置构建配置：

```text
Project name: corpusflow-demo 或最终项目名
Framework preset: Vite
Build command: npm run build
Build output directory: dist
Root directory: 留空
```

9. 设置环境变量：

```text
VITE_API_BASE_URL=https://api.example.com
NODE_VERSION=22
```

10. 点击 `Save and Deploy`。
11. 部署完成后记录 Pages URL：

```text
https://<project-name>.pages.dev
```

需要准备的信息：

```text
API 公网 HTTPS 地址
Cloudflare Pages 项目名
GitHub 仓库是否已推到远端
用于发布的分支名
Cloudflare 账号是否已授权访问该仓库
```

### Direct Upload 发布

适合临时预览或比赛前紧急发布。

步骤：

```bash
npm run build
npx wrangler pages deploy dist --project-name=<PROJECT_NAME>
```

注意：

- Direct Upload 项目创建后不能直接切换成 Git integration；如果后续需要 Git 自动部署，应新建 Git 集成项目。
- 拖拽上传适合纯静态资产；如果项目后续引入 `functions/`，应使用 Wrangler。
- 当前第一版不引入 Pages Functions，因此 Direct Upload 可作为备用快速路径。
- 本机没有全局 `wrangler`，但可通过 `npx wrangler` 使用；当前探测到版本为 `4.88.0`。
- 如果走 Direct Upload，需要先确认允许执行 `npm run build` 和 `npx wrangler pages deploy dist --project-name=<PROJECT_NAME>`。

## 4. 后端环境变量

### Express API

```text
PORT=3000
ALGORITHM_BASE_URL=http://algorithm:8001
JWT_SECRET=<比赛演示专用强随机值>
```

要求：

- `JWT_SECRET` 使用比赛演示专用值，不复用个人长期密钥。
- `ALGORITHM_BASE_URL` 在容器内优先使用内网地址；如果两服务不在同一网络，使用算法服务公网 HTTPS 地址。
- 如果前端部署在 Cloudflare Pages，Express API 需要支持 HTTPS 访问。

### FastAPI algorithm

```text
ARK_BASE_URL=https://ark.cn-beijing.volces.com/api/v3
ARK_API_KEY=<比赛演示专用 key>
ARK_MODEL=doubao-seed-1-6-250615
ARK_TIMEOUT_SECONDS=120
```

要求：

- `ARK_API_KEY` 不进入前端、不进入仓库、不进入录屏。
- 比赛演示 key 单独创建，赛后可撤销或轮换。
- 模型超时要覆盖批量生成场景，录屏时建议目标数量小一些。

## 6. 最可能卡住的点

### 1. CORS

触发条件：

- Cloudflare Pages URL 是 `https://xxx.pages.dev`
- API 是 `https://api.example.com`
- 浏览器跨域请求 Express API

现象：

- curl 请求成功。
- 浏览器请求失败。
- DevTools Console 出现 CORS policy 报错。

处理策略：

- 等算法 agent 完成后，再决定是否给 Express API 加最小 CORS 允许列表。
- 只允许演示 Pages 域名和本地开发域名，不建议比赛前开放 `*` 携带认证请求。

### 2. 算法服务慢

触发条件：

- 录屏时单批样本过多。
- LLM API 响应慢或限流。

处理策略：

- 录屏使用固定演示 CSV，优先 3-5 条稳 case。
- 并发设为 4。
- 其他生成参数保持产品现状，尤其仿写参数不调低。
- 如果等待超过 10 秒，暂停录制，生成完继续。

### 3. 前端构建变量没生效

现象：

- 前端仍请求 Pages 同域 `/api/...`。
- Network 里请求地址不是外部 API。

检查：

- Cloudflare Pages 中是否设置 `VITE_API_BASE_URL`。
- 是否重新触发了构建。
- 变量是否设置在对应 production / preview 环境。

### 4. Direct Upload 与 Git 集成路径混用

风险：

- Direct Upload 项目不能直接切换 Git integration。

策略：

- 正式项目优先 Git integration。
- Direct Upload 只作为临时预览或应急发布。

## 7. PPT 大纲

建议 10-12 页，顺序按比赛要求走：

```text
问题定位 -> 作品功能 -> 技术实现 -> 应用效果
```

### Slide 1: 标题页

标题：

```text
CorpusFlow：LLM 微调数据工程平台
```

副标题：

```text
把微调数据从手工作坊升级为工业化生产线
```

画面：

- 左侧产品名和一句话定位。
- 右侧产品工作台截图。
- 页脚放参赛队伍、仓库、演示 URL。

讲述重点：

- CorpusFlow 解决训练数据如何稳定、批量、可追溯地产出。
- 它不是 Prompt 工具，而是微调数据生产工作台。

### Slide 2: 问题定位 1 - 微调效果卡在数据质量

核心观点：

```text
大模型微调不是缺一次生成能力，而是缺稳定的数据生产能力。
```

内容：

- 人工写样本：质量可控，但速度慢、成本高、依赖专家经验。
- 批量让 LLM 生成：速度快，但容易语义漂移、实体丢失、幻觉混入训练集。
- 线上 badcase：价值高，但从日志到训练资产周期长。

### Slide 3: 问题定位 2 - Prompt 批量生成的问题

核心观点：

```text
直接 Prompt 批量生成，本质上把质量控制留给了事后人工抽检。
```

内容：

- 输入不结构化：约束散在 Prompt 里。
- 过程不可审计：不知道模型为什么这么变。
- 结果难复用：每次任务都重新写 Prompt。
- 质检滞后：坏数据进入训练集后才暴露问题。

### Slide 4: 作品定位 - 结构化约束生成范式

核心观点：

```text
字段识别 + 语义约束 + 批量生成 + 拒识保留，让样本生产从手工走向流程化。
```

画面：

```text
原始 CSV / badcase
  -> 字段识别
  -> 语义约束
  -> 实体 / 动作 / 数值 / 位置泛化
  -> 拒识保留
  -> JSON / CSV / JSONL 导出
```

内容：

- 字段识别减少人工清洗。
- 生成约束避免无边界聊天。
- 拒识保留让敏感或不适合生成的样本可审计。

### Slide 5: 作品功能 1 - 快速任务台

核心观点：

```text
面向大批量数据任务，弱编辑、重吞吐。
```

功能：

- 文件导入。
- 字段识别。
- 生成意图配置。
- 生成规模、多样性、质量过滤、并发设置。
- 开始、暂停、停止、继续。
- JSON、CSV、JSONL 导出。

截图建议：

- 左侧控制区。
- 中央数据预览和生成结果。
- 生成数、保留数、通过率。

### Slide 6: 作品功能 2 - 精调生成工作台

核心观点：

```text
用显性 case 展示实体、动作、数值、时间和位置泛化。
```

功能：

- 车控指令：`帮我把空调打开到22度`。

- 展示设备、温度、动作、歌手、作品类型、时间、位置、菜系、偏好泛化。

### Slide 7: 作品功能 3 - 数据资产闭环

核心观点：

```text
CorpusFlow 把线上问题转成可训练资产。
```

画面：

```text
线上对话 / badcase
```

## 8. 录屏准备

建议时长：4-5 分钟。

目标：让评委在不读代码的情况下明白 CorpusFlow 不是普通生成器，而是可控的数据生产流程。

### 录前准备

- 浏览器缩放设为 90% 或 100%。
- 关闭通知和无关标签页。
- 使用 demo 账号。
- 准备样例 CSV。
- 确认线上 URL、API、算法服务都已通过验收。
- 不展示终端密钥、`.env.local`、Cloudflare token、Ark API key。

### 样例 CSV

```csv
query,expected
帮我把空调打开到22度,识别车载空调控制意图，生成温度、动作和设备表达的多样化训练样本
周杰伦最近有新歌吗,识别音乐查询意图，生成歌手、作品类型和时间表达的多样化训练样本
找一下附近好吃的川菜馆,识别本地餐饮搜索意图，生成位置、菜系、口味和推荐约束的多样化训练样本
导航去虹桥机场，尽量避开拥堵,识别导航规划意图，生成目的地、路线偏好和避堵表达的多样化训练样本
帮我查一下附近有没有能充电的停车场,识别车载补能和停车搜索意图，生成充电、停车、距离和可用性相关样本
```

### 录屏路径

```text
0:00-0:20  打开线上 URL，展示产品标题和工作台
0:20-0:50  进入快速任务
0:50-1:30  导入 CSV，展示字段识别和预览
1:30-2:10  配置生成意图、数量、过滤强度、并发
2:10-2:50  开始生成，展示进度和统计
2:50-3:20  查看结果，导出 JSONL
3:20-4:20  切到精调生成，展示语义骨架和训练样本预览
4:20-4:50  回到全景或架构图，总结价值
```

### 推荐生成参数

```text
生成意图：
生成用于训练车载与生活助手的高质量指令样本，保留用户原始意图，扩展实体、动作、数值、时间和位置表达，避免编造不可验证事实。

并发：4
每条种子目标数量：保持当前产品默认/现状
过滤强度：保持当前产品默认/现状
仿写相关参数：保持当前产品默认/现状，不调低
```
