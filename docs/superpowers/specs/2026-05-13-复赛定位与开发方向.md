# CorpusFlow 复赛定位与开发方向

日期：2026-05-13

## 当前背景

CorpusFlow 已进入 NEXTAI 赛事赛道三「研发效能·提质增效」复赛，当前顺位为 14/50。复赛将在 2026-05-27 至 2026-05-28 现场进行路演评审。

复赛规则关键信息：

- 赛道三复赛采用现场演示制。
- 演示时长为 10 分钟。
- 无答辩环节。
- 评委现场打分，最终按平均分排序。
- TOP 5 晋级决赛。
- 第 6-15 名获得 Sigma-西格玛奖。

当前目标不是只保留现有演示，而是在复赛前做一次定位修正和针对性功能增强：稳住前 10 名，争取冲击 TOP 5。

## 赛道三评分约束

赛道三复赛基础评分满分 100 分，另有创新自主加分 0-10 分。公开规则中明确的评分维度包括：

- 技术价值
- 复用性与扩展性
- 性能 / 效率提升
- 业务支撑能力
- 现场演示效果

同分优先级：

1. 功能实用性与完成度
2. 技术创新与 AI 应用
3. 问题定位与价值
4. 应用效果与量化证明

这意味着复赛开发不应只追求「多做功能」，而应优先补强以下证据：

- 真实研发问题是否清晰。
- AI 应用是否体现技术含量，而不是简单套壳。
- 功能链路是否完整、稳定、可演示。
- 是否有可量化的效率提升或质量提升证明。
- 是否能跨多个研发场景复用。

## 竞品环境判断

已知复赛作品中，存在大量单点 AI 工具和插件：

- 代码生成、Bug 修复、研发流水线、质量工具。
- 测试用例生成、座舱测试、故障定位、故障码解析。
- Figma、HMI、造型设计、网页生成、浏览器插件。
- CATIA、CAE、ADAMS 等工程专业工具。
- 数据助理、需求对齐、问题闭环、知识沉淀类平台。

这些项目多数会围绕「降本增效」叙事展开。单纯讲节省人力，很难形成足够大的差异。

CorpusFlow 的机会在于：不要被讲成一个「数据生成工具」，而要讲成企业 AI 应用持续进化所需的训练与评测数据闭环平台。

## 定位修正

原定位：

```text
面向微调与评测的可控数据蒸馏工程平台
```

复赛建议定位：

```text
CorpusFlow：面向企业 AI 应用的训练与评测数据闭环平台
```

路演口语化表达：

```text
让研发过程中的 badcase、测试用例、用户反馈，自动沉淀为可复用的微调数据和评测资产。
```

这个定位的核心变化：

- 从「生成训练数据」升级为「构建 AI 应用迭代闭环」。
- 从「单点工具」升级为「研发效能基础设施」。
- 从「降本增效」升级为「让企业 AI 应用持续变好」。
- 从「演示大模型能力」升级为「演示数据工程、质量控制、复用导出能力」。

## 核心叙事

企业内部 AI 工具越来越多，但上线后都会遇到同一个问题：

```text
模型回答错了、测试失败了、用户反馈来了，这些 badcase 如何进入下一轮训练和评测？
```

过去的做法通常是：

- badcase 散落在日志、表格、飞书文档、测试记录里。
- 人工整理字段、清洗格式、补充期望答案。
- 手工改成训练数据或评测数据。
- 很难保留来源、拒识原因、风险标签和生成配置。

CorpusFlow 要解决的不是「再生成一些文本」，而是把这些失败信号变成可复核、可导出、可复用的数据资产。

## 复赛版本功能方向

建议将复赛版本定义为：

```text
CorpusFlow Competition Edition：badcase 回流与评测增强闭环
```

优先开发四个低风险、高路演价值的能力。

### 1. Badcase 回流评测集生成

目标：把用户反馈、测试失败样本、FAQ、需求问答、座舱 query 转成标准评测资产。

示例输出：

```json
{
  "id": "case_001",
  "domain": "座舱语音",
  "source": "badcase",
  "instruction": "我快没油了，帮我找顺路加油站",
  "expected_behavior": "推荐顺路加油站，并说明绕行成本",
  "risk_tags": ["位置服务", "出行安全"],
  "eval_points": ["是否确认当前位置", "是否说明绕行成本", "是否避免无关推荐"]
}
```

价值：

- 直接贴合赛道三「技术价值」和「业务支撑能力」。
- 让 CorpusFlow 从训练数据生产延展到评测数据生产。
- 可以服务座舱、售后、测试、需求、知识库等多个场景。

### 2. 数据质量体检报告

目标：生成后自动展示一页可讲解的质量与效率结果。

建议指标：

- 原始样本数。
- 有效样本数。
- 拒识样本数与拒识原因。
- 字段识别成功率。
- 生成样本数。
- 生成保留率。
- 导出格式覆盖情况。
- 预计节省人工整理时间。

价值：

- 直接服务「应用效果与量化证明」。
- 降低评委理解成本。
- 让现场演示从「看流程」变成「看结果」。

### 3. 行业模板与示例数据

目标：提供复赛演示可直接选择的行业模板，避免现场临时输入不稳定。

建议模板：

- 座舱语音 badcase。
- 售后知识库 FAQ。
- 测试用例扩写。
- 需求澄清问答。
- 故障码解释样本。

价值：

- 强化「复用性与扩展性」。
- 让评委直观看到该平台不是单场景工具。
- 支撑 10 分钟路演中的多场景横向展开。

### 4. 训练包 + 评测包组合导出

目标：把现有 JSON / CSV / JSONL 导出包装成更工程化的资产包。

建议导出结构：

```text
train_alpaca.jsonl
eval_cases.jsonl
rejected_cases.csv
quality_report.json
```

价值：

- 强化「工程平台」而不是「页面工具」的观感。
- 让结果可进入后续微调、评测、人工复核或归档流程。
- 对现场演示很直观。

## 建议开发优先级

优先级按复赛打分收益排序：

1. 数据质量体检报告。
2. Badcase 到评测集生成。
3. 行业模板与示例数据。
4. 训练包与评测包组合导出。

暂不建议在复赛前扩展为完整 EvalOps 平台。CorpusFlow 不应承担评测执行器、LLM Judge、CI Gate、基线对比平台等重功能。当前最清晰的边界是：

```text
不负责运行评测，而负责把评测失败和业务 badcase 转成下一轮训练 / 评测可用的数据资产。
```

## 10 分钟路演结构草案

建议路演按以下节奏组织：

| 时间 | 内容 | 目的 |
| --- | --- | --- |
| 0:00-1:00 | 问题定位：AI 工具上线后，badcase 很难回流成训练与评测资产 | 抬高问题价值 |
| 1:00-2:00 | 产品定位：CorpusFlow 是企业 AI 应用训练与评测数据闭环平台 | 建立差异化 |
| 2:00-6:30 | 现场 Demo：上传 badcase / FAQ -> 字段识别 -> 敏感拒识 -> 批量生成 -> 质量报告 -> 导出资产包 | 证明完成度 |
| 6:30-7:30 | 技术方案：字段契约、拒识、安全、格式标准、人工复核、可追溯导出 | 证明技术价值 |
| 7:30-8:40 | 复用场景：座舱、售后、测试、需求、知识库、研发 Agent | 证明扩展性 |
| 8:40-9:30 | 量化收益：整理时间、样本规模、保留率、拒识率、导出格式 | 证明应用效果 |
| 9:30-10:00 | 总结：让每一次 badcase 都成为下一轮 AI 能力提升的资产 | 留下记忆点 |

## 后续待办

compact 后建议从以下任务继续：

1. 将本文转成正式复赛功能规格。
2. 明确复赛版本 UI 改动范围。
3. 设计演示数据集，优先使用非敏感、车企研发可理解的样例。
4. 实现数据质量体检报告。
5. 实现 badcase / eval case 导出结构。
6. 准备 10 分钟 PPT 页结构与逐字讲稿。
7. 准备现场备用录屏，避免网络或模型响应波动影响演示。

## 当前决策摘要

- 赛道三是 10 分钟现场演示，不是 5 分钟。
- 复赛目标是保优秀奖、争 TOP 5。
- 定位应从「数据生成工具」升级为「训练与评测数据闭环平台」。
- 复赛开发优先服务评分项，不追求大而全。
- 当前最值得做的功能是质量报告、badcase 回流评测集、行业模板、组合导出。
- 产品边界是不做完整评测平台，而做评测失败到数据增强之间的桥梁。
