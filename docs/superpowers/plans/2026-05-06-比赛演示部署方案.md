# 比赛演示部署方案 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在最短时间内拿到稳定可提交的 CorpusFlow 线上演示 URL，同时保留后续迁移到 Cloudflare-only 架构的路径。

**Architecture:** 第一阶段采用 Cloudflare Pages 承载 Vite React 前端，后端 API 与 Python 算法服务部署到 Render，前端通过 `VITE_API_BASE_URL` 指向 Render 公网 API。第二阶段再把 Express API 改造为 Cloudflare Pages Functions / Workers，并用 D1、R2、KV 或 Durable Objects 替换本地文件和内存状态。

**Tech Stack:** React 19、Vite 6、Express、FastAPI、Docker、Cloudflare Pages、Cloudflare Workers / Pages Functions、Cloudflare D1 / R2 / KV。

---

## 结论

比赛演示优先选择 **Cloudflare Pages + Render 外部后端**。

原因：

- 前端是标准 Vite SPA，Cloudflare Pages 可直接构建，配置为 `npm run build`，输出目录 `dist`。
- 当前 `server.ts` 是 Express 常驻服务，并依赖本地 `data/*.json` 文件持久化任务、种子、生成结果和工作区状态。
- 当前 `algorithm/src/app.py` 是 FastAPI 算法服务，包含 LLM 调用、批量生成、线程池、任务进度和取消状态。
- Cloudflare Workers / Pages Functions 可以承接轻量 API，但不能无改造地运行当前 Express + 本地文件系统 + Python 常驻服务组合。
- Cloudflare Python Workers 支持 FastAPI，但截至 2026-05-06 仍处于 beta；比赛提交需要稳定优先，不建议第一版把核心算法服务押在 beta 运行时上。

## 当前项目部署边界

| 模块 | 当前实现 | 可否直接上 Cloudflare Pages | 推荐第一版 |
|---|---|---:|---|
| 前端工作台 | `src/` + Vite | 可以 | Cloudflare Pages |
| Node API | `server.ts` + Express | 不可直接作为 Pages 静态站运行 | Render Web Service |
| 任务/数据持久化 | `data/*.json` | 不适合 Worker 原样使用 | Render 容器磁盘或外部数据库 |
| Python 算法 | `algorithm/src/app.py` + FastAPI | 不建议第一版直接迁移 | Render Web Service |
| LLM 密钥 | `.env.local` / 环境变量 | 不能进入前端 | 后端 Secret |

```
  │  https://corpusflow-algorithm.onrender.com

```

当前线上链路：

```text
https://corpusflow-demo.pages.dev
  -> VITE_API_BASE_URL=https://corpusflow-app.onrender.com
  -> Express /api/*
  -> ALGORITHM_BASE_URL=https://corpusflow-algorithm.onrender.com
  -> FastAPI /health、/quick-generate、/progress/:jobId
```

注意：`https://corpusflow-demo.pages.dev/api/*` 不是正式 API 入口。Cloudflare Pages 当前只托管静态前端；API 请求必须由前端构建变量指向 Render。

### 部署配置

Cloudflare Pages：

- Build command: `npm run build`
- Build output directory: `dist`
- Node version: 使用 Cloudflare Pages 当前默认 Node 22，或在项目设置里显式指定 Node 22。
- Environment variable:
  - `VITE_API_BASE_URL=https://corpusflow-app.onrender.com`

Render 后端：

- 部署 `app` 服务，建议使用仓库根目录 `Dockerfile`，生产启动命令为 `npm run start`。
- 部署 `algorithm` 服务，建议使用 `algorithm/Dockerfile`，启动命令为 `uv run --project algorithm python algorithm/run.py`。
- `app` 环境变量：
  - `PORT=3000`
  - `ALGORITHM_BASE_URL=https://corpusflow-algorithm.onrender.com`
  - `JWT_SECRET=<强随机值>`
- `algorithm` 环境变量：
  - `ARK_BASE_URL=https://ark.cn-beijing.volces.com/api/v3`
  - `ARK_API_KEY=<比赛演示专用 key>`
  - `ARK_MODEL=doubao-seed-1-6-250615`
  - `ARK_TIMEOUT_SECONDS=120`

### 验收标准

- [ ] Cloudflare Pages 访问首页成功。
- [ ] `https://corpusflow-app.onrender.com/api/health` 返回 `node: true` 和 `algorithm.ok: true`。
- [ ] 新建任务、导入种子、保存工作区、生成数据、导出 JSON/CSV/JSONL 完整跑通。
- [ ] 浏览器 DevTools 中没有混合内容、CORS、401/403 或 5xx 错误。
- [ ] 演示账号和 API key 使用比赛专用配置，不复用个人长期密钥。

### 快速排障

1. Pages 首页打不开：检查 Cloudflare Pages 最新部署和静态资源路径。
2. 页面能打开但无法登录/拉任务：检查前端构建产物中的 `VITE_API_BASE_URL` 是否为 `https://corpusflow-app.onrender.com`。
3. `https://corpusflow-app.onrender.com/api/health` 中 `node: true`、`algorithm.ok: false`：Express 已启动，但 Render 上的 `corpusflow-algorithm` 未启动、休眠、启动失败，或 `ALGORITHM_BASE_URL` 配置错误。
4. 生成接口 502：优先检查算法服务日志、`ARK_API_KEY`、`ARK_MODEL`、`ARK_TIMEOUT_SECONDS` 和 Render 服务冷启动。
5. 直接请求 `https://corpusflow-demo.pages.dev/api/health` 得到 HTML：这是静态 Pages fallback，不代表后端可用。

## 第三版：Cloudflare-only 探索

这一版只在第一版比赛演示稳定后启动。

方向：

- 用 Python Workers beta 尝试迁移 FastAPI 算法服务。
- 用 `pywrangler` 管理 Python Worker 依赖。
- 将进度状态迁移到 Durable Objects。
- 将异步批量任务迁移到 Queues 或 Workflows。
- 对免费档 CPU、内存、请求数做压测；如果触发 `Worker exceeded resource limits`，保留外部算法服务。

风险：

- Python Workers 仍是 beta，核心算法服务存在运行时不确定性。
- Workers Free plan 每日请求数、CPU 时间、内存、子请求数量均有限。
- 批量生成的响应体和进度状态比普通 CRUD API 更容易踩边缘运行时限制。

### Slide 1: 标题页

**标题：** CorpusFlow：LLM 微调数据工程平台

**副标题：** 把微调数据从手工作坊升级为工业化生产线

### Slide 2: 问题定位 1 - 微调效果卡在数据质量

**核心观点：** 大模型微调不是缺一次生成能力，而是缺稳定的数据生产能力。

**内容结构：**

- 人工写样本：质量可控，但速度慢、成本高、依赖专家经验。
- 批量让 LLM 生成：速度快，但容易语义漂移、实体丢失、幻觉混入训练集。
- 线上 badcase：价值高，但从日志到训练资产周期长。

**画面建议：**

- 三个痛点卡片：人工慢、批量飘、闭环长。
- 中间用一句话收束：规模、可控、闭环，很难同时满足。

### Slide 3: 问题定位 2 - 现有方案的问题

**核心观点：** 直接 Prompt 批量生成，本质上把质量控制留给了事后人工抽检。

**内容结构：**

- 输入不结构化：约束散在 Prompt 里。
- 过程不可审计：不知道模型为什么这么变。
- 结果难复用：每次任务都重新写 Prompt。
- 质检滞后：坏数据进入训练集后才暴露问题。

**画面建议：**

- 对比表：Prompt 游乐场 vs 数据工程生产线。
- 强调 CorpusFlow 要做后者。

### Slide 4: 作品定位 - 结构化约束生成范式

**核心观点：** 人管结构，模型管规模。

**内容结构：**

- 第一步：语义骨架构建，人审人调，锁定语义边界。
- 第二步：实体填充扩展，LLM 在边界内做规模化变体。
- 第三步：质量门控，做实体一致性与语义相似度过滤。

**画面建议：**

```text
种子数据 → 语义骨架 → 实体扩展 → 质量过滤 → 训练数据
          ↑ 人审结构       ↑ 模型扩量       ↑ 自动质检
```

### 录前准备

- 本地或线上服务已启动。
- 准备一个演示账号，例如 `demo@corpusflow.local`。
- 浏览器缩放设置为 100% 或 90%，避免界面挤压。
- 关闭通知、菜单栏杂项、无关浏览器标签。
- 准备 3 条种子数据，主题建议统一为“车载助手”或“旅游助手”，便于评委理解。
- 如果使用快速任务导入，准备一个 CSV 文件：

```csv
query,expected
帮我查询明天早上从北京南到上海虹桥的高铁票,返回可选车次、出发时间、到达时间和余票情况
我想找一家适合带老人吃饭的杭州本帮菜餐厅,推荐餐厅并说明位置、口味和是否适合老人
车机导航帮我避开拥堵，优先走高速去虹桥机场,生成导航规划并说明避堵策略
```

### 推荐录屏工具

优先推荐：**Screenize**。

理由：

- 官方页面说明它是免费开源的 macOS 录屏工具。
- 支持自动缩放到光标、点击效果、快捷键覆盖和时间线编辑。
- 适合录产品演示，比 OBS/QuickTime 少很多后期工作。
- 需要 macOS 13.0 或更高版本。

备选：

- **Recordly**：开源、跨 macOS / Windows / Linux，支持自动 zoom 建议、光标平滑、背景和时间线编辑。
- **Open Screen**：免费开源，支持跟随光标的自动缩放、注释、背景、MP4/GIF/WebM 导出。
- **OBS + auto zoom 脚本**：可控性强，但配置成本高，不建议比赛前临时折腾。

工具资料：

- Screenize：<https://castle-yein.com/screenize/>
- Recordly：<https://github.com/webadderallorg/Recordly>
- Open Screen：<https://openscreen.net/>
- OBS auto zoom 脚本线索：<https://github.com/kareem-studio/OBS-Screen-Studio-script>

### 逐句旁白稿

#### 0:00-0:20 开场

画面：打开 CorpusFlow 首页或工作台。

旁白：

> 大家好，这是 CorpusFlow，一个面向大模型微调的数据工程平台。它解决的不是“让模型生成一句话”，而是把微调数据从手工 Prompt，升级成可控、可批量、可追溯的数据生产流程。

操作：

- 鼠标停在产品标题或主工作区。
- 不要急着点击，先让评委看清界面。

#### 0:20-0:50 进入快速任务

画面：点击“快速任务”。

旁白：

> 在真实团队里，最常见的是批量构造训练数据、评测集，或者围绕线上 badcase 做定向增强。CorpusFlow 把这些需求抽象成任务卡，用户配置业务约束，而不是反复手写 Prompt。

操作：

- 点击“快速任务”入口。
- 展示左侧控制流和中央“数据预览 / 结果”区域。

#### 0:50-1:30 导入种子数据

画面：点击快速导入，选择 CSV 文件。

旁白：

> 我这里导入一组种子数据。系统会解析文件，并识别 query、expected、instruction 等字段。种子不是直接丢给模型批量扩写，而是作为后续结构化生成的输入资产。

操作：

- 点击“快速导入”。
- 选择准备好的 CSV。
- 等待字段识别和预览出现。
- 鼠标扫过字段识别结果、种子数量、预览列表。

#### 1:30-2:10 配置生成约束

画面：展开控制区，配置生成意图、生成规模、质量过滤。

旁白：

> 这里可以配置生成意图、每条种子生成多少条、过滤强度、多样性和并发。核心思想是先把业务边界说清楚，再让模型在边界内扩量，避免无约束批量生成带来的语义漂移。

操作：

- 在“生成意图”输入：

```text
生成用于训练车载/生活助手的高质量问答样本，保留用户真实意图，避免编造具体不可验证信息。
```

- 将每条种子目标数量设为 5 或 10，比赛录屏建议用小数量，避免等待太久。
- 质量过滤选择“中”或“严格”。
- 并发保持默认或设为 2-3。

#### 2:10-2:50 开始生成

画面：点击“开始生成”，展示进度条和统计。

旁白：

> 点击开始后，系统会调用后端算法服务进行生成与过滤。这里可以看到生成数量、保留数量和通过率。对长任务，也支持暂停、继续和停止，避免一次批量任务失控。

操作：

- 点击“开始生成”。
- 等待至少出现进度卡片。
- 如果模型响应较慢，录屏时可以暂停录制，生成完继续。
- 鼠标停在生成、保留、通过率三个指标上。

#### 2:50-3:20 查看与导出结果

画面：展示结果列表，点击 JSONL 导出。

旁白：

> 生成完成后，结果会按训练格式呈现。这里可以直接导出 JSON、CSV 或 JSONL。JSONL 可以直接进入微调或评测流水线，避免人工再做格式整理。

操作：

- 滚动结果区，展示 2-3 条生成结果。
- 点击 JSONL 导出。
- 如果浏览器下载提示出现，不需要展开下载目录。

#### 3:20-4:20 展示精调生成

画面：切换“精调生成”，输入一条高价值种子，生成预览。

旁白：

> 对更高价值的样本，可以进入精调生成工作台。这里不是直接生成结果，而是先拆出意图、主体、动作、对象和修饰条件，再基于这些语义骨架做候选扩写和训练样本生成。人可以检查结构，模型负责扩量。

操作：

- 切换到“精调生成”。
- 输入种子：

```text
车机导航帮我避开拥堵，优先走高速去虹桥机场
```

- 点击“生成预览”。
- 展示语义解析、候选扩写、训练样本预览。
- 如果已有生成好的工作区，优先使用已有任务，减少等待。

#### 4:20-4:50 收束

画面：回到 README 架构图、PPT 总结页或工作台全景。

旁白：

> 总结一下，CorpusFlow 的价值是把线上问题、种子样本和评测需求，转成可审计、可导出、可回流训练的数据资产。它让微调数据生产从经验驱动，升级为策略驱动。

操作：

- 停在架构图或工作台全景。
- 不要继续点新功能。

### 录屏注意事项

- 录屏时只展示一条主路径，不要把所有功能都点一遍。
- 每个动作前让鼠标停 0.5 秒，方便跟随光标的自动缩放捕捉焦点。
- 如果模型生成超过 10 秒，直接暂停录制，生成完成后继续。
- 不要展示真实 API key、`.env.local`、终端密钥、浏览器密码管理器。
- 最终导出建议：MP4、1080p、30fps，码率 8-12 Mbps。

## 比赛产片清单

建议最终交付四个材料：

- `PPT`：10-12 页，按“问题定位、作品功能、技术实现、应用效果”组织。
- `录屏视频`：4-5 分钟，按上面的脚本录制。
- `演示 URL`：Cloudflare Pages URL，能打开工作台。
- `样例产出包`：包含输入 CSV、导出的 JSONL、1 张架构图或流程图截图。

样例产出包命名建议：

```text
CorpusFlow-比赛演示材料/
  01-演示输入.csv
  02-生成结果.jsonl
  03-产品架构图.png
  04-演示说明.txt
```
